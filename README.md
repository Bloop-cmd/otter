# OTTI Live Final V2

Production-oriented Otti Messenger foundation with:

- PostgreSQL persistence
- Email/password authentication
- Google OAuth
- GitHub OAuth
- PostgreSQL-backed server sessions
- Authenticated WebSocket realtime chat
- Room membership enforcement
- Groups / Otti Circles
- Main-screen statuses
- Bright DIVE with golden ancient symbols
- Responsive Otti frontend

## Local

1. Create a PostgreSQL database.
2. Copy `.env.example` to `.env` and fill `DATABASE_URL` and `SESSION_SECRET`.
3. Run `npm install`.
4. Run `npm start`.
5. Open `http://localhost:10000`.

The application initializes its required application tables on startup. `schema.sql` is also included for inspection/manual provisioning.

## Production / Render

The repository includes `render.yaml`. Render creates:

- Web service: `otti-live`
- PostgreSQL database: `otti-postgres`

The Blueprint supplies `DATABASE_URL` from the database and generates `SESSION_SECRET`. OAuth secrets and `APP_URL` are entered as secret values during Blueprint setup or later in the Render Environment page.

### Required Render environment variables

```text
NODE_ENV=production
DATABASE_URL=<provided by Render Blueprint>
SESSION_SECRET=<generated by Render Blueprint>
APP_URL=https://YOUR-OTTI-DOMAIN
GOOGLE_CLIENT_ID=<Google OAuth client ID>
GOOGLE_CLIENT_SECRET=<Google OAuth client secret>
GITHUB_CLIENT_ID=<GitHub OAuth client ID>
GITHUB_CLIENT_SECRET=<GitHub OAuth client secret>
```

Render supplies `PORT`; the server binds to `0.0.0.0`.

### Production commands

Build:

```bash
npm install
```

Start:

```bash
npm start
```

which runs:

```bash
node server.js
```

### OAuth callback URLs

Replace `YOUR-OTTI-DOMAIN` with the exact HTTPS origin in `APP_URL`.

Google:

```text
https://YOUR-OTTI-DOMAIN/auth/google/callback
```

GitHub:

```text
https://YOUR-OTTI-DOMAIN/auth/github/callback
```

For local development:

```text
http://localhost:10000/auth/google/callback
http://localhost:10000/auth/github/callback
```

Do not commit OAuth secrets or `.env`.

## Health check

```text
GET /health
```

The endpoint checks PostgreSQL connectivity and returns HTTP 503 if the database is unavailable.

## Architecture

Browser → HTTPS/WSS → Express → PostgreSQL-backed session/auth → PostgreSQL data → authenticated WebSocket room.

WebSocket clients first obtain a short-lived one-time token from `/api/ws-token` using their authenticated session. The token is consumed during WebSocket upgrade, preventing anonymous room access.
